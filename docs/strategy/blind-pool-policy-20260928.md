# 未知 RNG：随机池估值与逐步观察策略

> 本文保留 2026-09-28 批次的结果与评分口径。后续对 PowerPotion/ColorlessPotion 通道及直接生成到手牌卡牌的验收见[随机池扩展验收](blind-pool-expansion-20260929.md)。

## 本轮结果

本轮在已同步的 `origin/main@7236330` 上修正随机池动作遗漏、原生药水选牌缺口，以及首动作复评直接采用样本全知路线的问题。实现位于 `codex/blind-rng`，入口仍是 OfflineSearchHarness 的 blind 模式；游戏内常规 UI 仍使用确定性求解器。

| 问题 | 当前处理 |
|---|---|
| 没有样本提名的随机池动作无法得到评分 | 补齐当前枚举入口准入的全部首命令，每个命令在全部外层样本上执行 |
| 攻击/技能药水生成三张后如何选 | 观察真实候选；每个候选和跳过使用同一组独立内层样本续搜，再应用选中牌 |
| 酸、添柴没有三选一页面 | 按原版随机池生成并完整结算，在生成牌可见后重新决定下一命令 |
| 添柴可能消耗比随机池更好的手牌 | 同一轨迹先结算消耗再评价后续用途，机会成本进入比较 |
| 一个样本知道自己下一张牌，导致不可能执行的策略拿到高分 | 外层每一步重新形成观察并独立采样决策，禁止部署该外层样本的后续路线 |
| 内层确定化搜索的乐观性 | 仍可能影响提名和药水选项的提案评分；最终首动作分数来自可执行的外层轨迹 |

这里的卡池评分使用原版生成分布与当前战斗状态。它不是把所有卡牌的静态分数简单平均：费用修正、手牌空间、当前威胁、可用能量和后续回合都在结算/搜索中参与。随机池只作有限采样，本轮没有穷举完整分布或证明最优。

## 如何避免知道样本未来

设外层样本 A 的隐藏牌序是甲、乙，样本 B 是乙、甲；两者当前手牌和意图相同。旧复评分别搜索 A/B 的最佳完整路线，可能在抽牌之前就按下一张牌安排资源。

现在每个首动作的复评执行以下过程：

1. 在外层样本上发起当前命令，使用现有模拟语义结算实际随机结果。
2. 动作完成后，`CombatRootSnapshot.ObservePrediction` 从影子状态冻结新观察，不读取 live 状态。
3. 决策器以固定 `DecisionSeed` 派生独立内层样本，替换九条未来 RNG、未知牌序、未来意图和后续怪物创建的 run RNG。
4. 内层 Coordinator 提名下一命令，按票数、平均提案分数和稳定键取一项；样本里的选择与后续路线全部剥离。
5. 在外层样本执行这个命令，直到终局或动作/回合/时间边界。最终按实际执行轨迹聚合。

这样，同一观察下的下一命令不依赖 A/B 尚未揭晓的 RNG 或牌序；抽到不同牌之后，手牌已经成为可见信息，可以选择不同命令。观察缓存使用重新采样后的状态戳，不能用外层样本 RNG 作缓存键。

内层仍用确定化搜索产生提案，因此这不是精确的部分可观测最优规划器。它的提案可能有偏差，但不会把该提案的全知后续分数直接记作外层首动作价值。药水选项的 `ValueScope=independent_determinized_choice_proposal` 明确保留这个区别。

## 选择与跨回合

- 药水通过已有 `PotionExecutionSupport.Prepare/Complete` 结算。检查点在消费槽位、运行 Use 后，应用选择与 `AfterPotionUsed` 前；每项选择从同一前缀独立完成。生成候选来自已经发生的生成事件，不重新抽三张。
- 攻击/技能药水的 0..1 张边界包含跳过，各三张牌和跳过都进入复评。原生选择器默认 `Blind`，也保留 `Stop` 和 `FirstLegal` 作为显式基线。
- 原生候选按逐实例语义键匹配。已支持的九种药水复用现有选择定义；本轮原生闭环直接验证攻击药水、技能药水和弃牌重抽药水，其余六种没有新增原生验收结论。
- 普通卡牌/回合内选择采用已有可见牌优先级；这保证不读未揭晓 RNG，但不保证局部最优。原生未知来源或第二层选择明确失败，没有来源定义时不猜测。
- EndTurn 走既有完整回合推进。每个新稳定观察重新决策；截断叶子使用重采样当前状态的威胁、可打手牌、未来资源和有上限的持续能力价值，没有全知尾部计划。
- `IsPredictionObservation` 让重建的模拟根不再调用 live `Original.CanPlayTargeting` 判断模拟首动作；普通 live 根保留原稳定阶段检查。
- 原生选牌任务持有独立的关联取消源；超时/取消先取消并排空 worker，再释放选择前缀。

合计 94 项检查通过。命令独立性检查用两个分别新建的决策器，排除“同一个缓存命中”造成的假通过；药水选择同时比较完整选项评分向量。外层种子确实不同，所有候选均执行其被约束的第一命令。搜索前后原生根状态不变。

Mod 与最终宿主 Release 构建均为 0 警告/0 错误。Windows 结构门禁为 `REFACTOR_BOUNDARIES_OK search_files=241`；两端同步登记 Blind 分文件和观察策略边界，只执行了 Windows 门禁。不启用 blind 的 Coordinator 最小回归完成零损胜利，2 展开/4 转移，证据为 `deterministic-final`；这是普通回放入口烟测，不代表全量策略回归。

### 分数怎样读

这些是三条外层可执行轨迹的结果。只有完整轨迹的 HP 才可当作该样本的整场战损；未完成项单列。

| 首命令 | 平均实际扣血 | 完成胜利样本 | 与对照的分数差 |
|---|---:|---:|---:|
| 攻击药水 | 1.33 | 3/3 | 比省药 EndTurn 低 110000 |
| 技能药水 | 0 | 3/3 | 比省药 EndTurn 低 30000 |
| 弃牌重抽药水 | 0 | 3/3 | 比省药 EndTurn 低 300000 |
| 直接 EndTurn（上述三个夹具） | 4 | 3/3 | 对照 |
| `BLUDGEON` | 0 | 3/3 | 比添柴高 240000 |
| 添柴 | 4 | 3/3 | 与直接 EndTurn 同分 |
| `OROBIC_ACID` | 2.67，仅已执行前缀 | 2/3 | 另 1 条为 time_limit，不作完整战损对照 |

药水平均减少了扣血而未被选中，是因为默认 Smart 仍计算保存药水的战略成本。以攻击药水为例，少掉 2.67 HP 的评分收益小于本次用药成本，不等于随机池被判为没有收益。

原生攻击药水实际候选为 `FIEND_FIRE`、`PILLAGE`、`RAMPAGE`。独立内层提案评分中，选 `PILLAGE` 预计扣血 0，其余两张和跳过均为 4，分数领先约 240000。该数值属于选牌提案；外层药水动作的平均实际扣血是 1.33，不能混成同一个数字。

## 预算与未验证项

`--budget-ms` 仍是软预算：每外层样本先做一次发现搜索，再把同等预算分给各候选的轨迹。轨迹中的内层搜索至少 25 ms/样本，并且选牌需要逐选项续搜；昂贵的单次同步结算、叶子评分和收尾可以超出软预算。相同候选配置不代表实际耗时或轨迹深度相同，缓存也会影响每次轨迹可走的深度。

每项评估输出 `ObservedActions`、`Decisions`、`StopReason` 和 `ValueScope`。完整结果为 `completed_policy_trajectory`；截断结果为 `observed_prefix_with_state_heuristic`。`SurvivalRate` 表示已经执行部分仍存活，`VictoryRate` 表示预算内已经完成胜利，不是统计战斗胜率。`Majority` 改用外层轨迹分数投票，默认聚合改为 `MeanScore`。

仍未完成全局可见字段白名单：怪物私有 AI/内部状态和第三方隐藏字段尚未逐项证明可从公开历史推导。当前采样假定玩家知道抽牌堆的卡牌多重集，仅不知道顺序；已知堆顶也只由观察者显式声明。不能将本轮 RNG/牌序独立性扩大为整个规划器的严格可见性保证。

本轮未做完整通关、统计胜率、Linux 门禁或可见游戏验证；没有提升版本、发包或推送。内层复用 Coordinator，保留 Smart 审计与跨回合计划入口，但 128 节点短预算不保证复杂长期计划搜索充分。原生复杂嵌套选择已于 2026-10-01 接入逐层评分(见交接 20260929 架构任务)；Mod 在线 blind UI 仍待接入。

## 重跑

```powershell
$env:OFFLINE_HARNESS_BLIND_POLICY_CHECKS = '1'
dotnet tools/OfflineSearchHarness/bin/Release/net9.0/OfflineSearchHarness.dll `
    --request tools/OfflineSearchHarness/fixtures/blind-pool-attack.json `
    --milestone M1 --blind-seed 902828 --beam 12 --nodes 300 --budget-ms 3000 --dop 1 `
    --workspace .local/blind-pool-repro/host-attack --out .local/blind-pool-repro/attack
```

其他随机池把夹具换为 `blind-pool-skill.json`、`blind-pool-acid.json`、`blind-pool-stoke.json` 或 `blind-pool-gambler.json`。延迟/立即击杀哨兵使用原 `OFFLINE_HARNESS_BLIND_AUDIT=delayed/immediate`，不要同时设置两种专项环境开关。
